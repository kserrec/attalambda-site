Learn AttaLambda from the ground up

Learn lambda calculus by watching AttaLambda disappear into it.

Start with a name, a function, and a function call. We will build up to data, runtime types, errors, recursion, and input and output. You do not need to know lambda calculus or Lisp to follow along.

The mathematical examples explain ideas. Blocks labeled “source excerpt” show implementation code; blocks labeled “conceptual view” are drawings in text. Complete runnable programs begin with #lang attalambda. The examples and source links here describe AttaLambda 0.8.0.

1. Three small building blocks

x refers to a value. We call such a name a variable.

λx.x describes a function that accepts one argument, names it x, and returns it. The Greek letter λ, pronounced “lambda,” starts the function; the dot separates its parameter from its body. Making a function this way is lambda abstraction. “Unary” just means it takes one argument.

f x applies the function f to the argument x. This is application: a function call.

The same three forms in two notations
IdeaCalculusAttaLambda
Variablexx
Unary functionλx.x(lambda (x) x)
Applicationf x(f x)

In AttaLambda, the function comes first inside the parentheses, followed by its argument. These are expression fragments, not complete programs.

Ordinary AttaLambda computation ultimately reduces to variables, one-argument lambdas, and application. The rest of this page shows how those three forms can do so much.

2. Applying a function

Apply the function by replacing its parameter with the supplied argument:

Lambda calculus

(λx.x) hello
→ hello

The body was just x, so replacing it with hello leaves hello. This simplification is called beta reduction. Here hello stands for some value; it is not a string literal.

Substitution replaces the occurrences belonging to this parameter. A name inside another function may belong to that other function instead. When necessary, bound parameters can be renamed to keep those meanings separate. We will use distinct names in the examples.

3. One argument at a time

A one-argument function can return another one-argument function:

Lambda calculus

λx.λy.x

Give it apple. The result is a function still waiting for y. Give that function orange, and it returns the apple it already has:

(λx.λy.x) apple
→ λy.apple

(λy.apple) orange
→ apple

Representing several arguments as a chain of one-argument functions is called currying. Supplying only the first argument is a partial application: it produces the function for the next one.

Application groups to the left: f x y means (f x) y. AttaLambda's (f x y) likewise expands into ((f x) y). A lambda body extends to the right, so λx.λy.x means λx.(λy.x).

4. What def gives us

AttaLambda lets us name that function and write its parameters together:

You write — declaration fragment

(def first x y = x)

Desugared — implementation syntax

(define first
  (lambda (x)
    (lambda (y)
      x)))

Lambda calculus — the value named first

λx.λy.x

def gives a name to the lambda value and provides friendlier syntax. It does not add another form of computation. Syntax that expands into simpler existing forms is called syntactic sugar. define above is the implementation's binding syntax, not an additional command to write in an .attl file.

The release's def macro constructs precisely these nested unary lambdas. Its language expander also expands multiple-argument calls one argument at a time.

5. A Boolean can choose

We have a function that chooses its first argument. A second function can choose its second argument. Those two behaviors give us a way to represent true and false:

Lambda calculus — raw Boolean selectors

raw-true  = λthen.λelse.then
raw-false = λthen.λelse.else

raw-true apple orange  → apple
raw-false apple orange → orange

A Boolean can be a function that selects one of two arguments. Data can be behavior. These equations show the meaning of the release's raw Boolean functions.

These are the internal, raw selectors. The public AttaLambda values TRUE and FALSE add a type tag around them. We will build that surrounding structure next.

AttaLambda evaluates lazily: an argument is evaluated when its value is needed. Selecting one branch therefore need not evaluate the other. This will also matter when we reach recursion.

6. A pair waits for a selector

To keep two values together, make a function that remembers both and lets its caller choose what to do with them. Here is AttaLambda's actual pair constructor:

Source excerpt — core/pair.rkt

(def raw-pair left right selector =
  ((selector left) right))

Lambda calculus

λleft.λright.λselector.
  selector left right

Supply values A and B. The function still waiting for a selector is the pair itself:

raw-pair A B
→ λselector.selector A B

(λselector.selector A B) (λleft.λright.left)
→ (λleft.λright.left) A B
→ A

(λselector.selector A B) (λleft.λright.right)
→ (λleft.λright.right) A B
→ B

The first selector retrieves the left value; the second retrieves the right value. The release's raw-first and raw-second do exactly this. A pair needs no primitive container: it is a function waiting for a selector.

Source: pair constructor and selectors. Names beginning with raw- here describe internal functions, not additional public commands.

7. From pairs to objects

Use the left side of a pair to identify what kind of value it is, and the right side for its contents. The identifier is the type tag; the contents are the payload. AttaLambda calls this an object.

Source excerpt — core/objects.rkt

(def raw-make-object type-tag value =
  ((raw-pair type-tag) value))

Replace raw-pair with its lambda and supply the tag and payload:

Lambda calculus — expanding the constructor

((λleft.λright.λselector.
    selector left right)
 type-tag)
 payload

→ λselector.selector type-tag payload

That selector function is the object value. Giving it the first selector retrieves the tag; giving it the second retrieves the payload. There is no hidden record underneath this lambda.

A shorter way to draw the same thing

Now that we have seen the actual representation, we can give its two positions human-readable labels:

Conceptual view — structural notation

{
  type: type-tag,
  value: payload
}

This is not another representation inside AttaLambda. Nothing has been converted into JSON, a JavaScript object, or a Racket struct. We are drawing the same lambda-encoded structure in a form that is easier to read. The field names are this guide's labels.

Structure and meaning

For a concrete example, Rat is the public numeric type: an exact rational number. Its tag is named church-seven. We will explain that name and the number payload shortly. For now, treat them as values filling the pair's two positions.

Actual lambda shape — payload abbreviated

λselector.selector church-seven <rat-payload>

Conceptual view — structural

{ type: church-seven, value: <rat-payload> }

Conceptual view — semantic, showing its meaning

{ type: "Rat", value: 42 }

The progression from actual lambda → structural view → semantic view changes our viewpoint, not the runtime value. The text "Rat" and the familiar number 42 summarize encoded values. Angle-bracketed names such as <rat-payload> mark omitted structure; they are not executable syntax.

We will keep this convention for all the values that follow. Source: object construction and access.

8. Public values and runtime types

Ordinary tagged public values share the outer shape we just built: a pair of type tag and payload. The payload differs by type.

Return to Booleans. Public TRUE wraps the first-argument selector in a Bool object; public FALSE wraps the second-argument selector.

Conceptual view — public TRUE and FALSE

{ type: "Bool", value: raw-true }
{ type: "Bool", value: raw-false }

A raw Boolean selects. A public Bool carries that selector as its payload, plus a tag identifying it as a Bool. Public if checks the condition's tag, then uses its raw payload to choose a branch.

Similarly, add expects Rat arguments. Public operations inspect the tags their contracts require while the program runs. A mismatch between an expected tag and an argument's actual tag produces an Error value. We will inspect one below.

This is runtime type checking. There is no compile-time static type system proving that every call has the right arguments. The underlying lambda calculus remains untyped. Tags are values and checks are computations built inside it; this is not a blanket safety promise about arbitrary untagged functions.

Sources: public Booleans and runtime argument checking.

9. Type tags made of lambdas

If type identity must stay inside the lambda universe, what can a type tag be? We need a small set of distinct values. A function can encode a small number by applying a supplied step function that many times to a starting value:

Lambda calculus — Church numerals

0 = λf.λx.x
1 = λf.λx.f x
2 = λf.λx.f (f x)
3 = λf.λx.f (f (f x))

For example, the function labeled 2 accepts f and x, then applies f twice. Such functions are called Church numerals. The left-hand digits label mathematical encodings here; an AttaLambda numeric literal uses the different representation in the next section.

Public type-tag assignments in AttaLambda 0.8.0

3Unused by current public types
4Result

7Rat
8Unit

11Map

Now { type: church-seven, value: <rat-payload> } has a more precise meaning: the tag is a function that performs seven steps. The tag comparison is also implemented with lambdas.

These assignments come from core/tags.rkt. Church numerals also encode small metadata such as Error kinds and argument positions.

10. Practical numbers

Church numerals are used for tiny tags and metadata, not AttaLambda's ordinary arithmetic. Ordinary numbers are exact Rats: a signed numerator over a positive denominator, reduced to lowest terms. Whole numbers such as 42 are Rats too.

The magnitudes underneath use lists of binary digits, with raw Booleans representing the bits. The list, the sign, and the surrounding pairs are all lambda-encoded. A number's size is not represented by repeating a function that many times.

Complete program

#lang attalambda

(print (add 1/3 1/6))

Output (no trailing newline)

1/2

#lang attalambda selects the language for a program file. print renders a value as text; we will follow that text out to the world in the host section.

See the number payload

A Rat object contains a raw pair of numerator and denominator. The numerator is another raw pair: a Boolean sign (true means nonnegative) and magnitude bits. The denominator is positive magnitude bits. In the structural notation below, pair(a, b) abbreviates the same selector function we derived earlier.

Conceptual view — payload structure

{
  type: church-seven,
  value: pair(
    pair(<sign>, <numerator-bits>),
    <denominator-bits>
  )
}

For 42, the sign is raw true, the numerator bits represent binary 101010, and the denominator bits represent 1. Zero is normalized to positive 0/1.

Sources: rational payloads, signed numerators, binary magnitudes.

11. Lists are linked values

A List holds a sequence of values. In the friendly view, the result of (list 1 2 3) looks like this:

Conceptual view — semantic

{ type: "List", values: [1, 2, 3] }

values and the square brackets summarize the sequence; no host array is stored. A nonempty List is an object whose payload is a pair: its first element, called the head, and the remaining List, called the tail.

Conceptual view — one node

{
  type: "List",
  value: pair(<Rat 1>, <List containing 2 and 3>)
}

Here and below, pair(a, b) is drawing shorthand for λselector.selector a b. Follow each tail to get the next node. After the last element, the tail is NIL, the canonical empty List.

Source excerpt — nonempty node construction

(def raw-cons value tail =
  ((raw-make-object list-type)
   ((raw-pair value) tail)))

The special NIL object has an empty-list Error sentinel in both payload positions, instead of a normal head and tail. The implementation recognizes the end by the Error tag in the tail position. Calling public head or tail on NIL yields an Error.

Sources: raw-cons and canonical NIL, List access and operations. We only need the node structure here; the public operations are summarized in Language.

12. Option: was there a value?

A search can legitimately find nothing. Option represents that expected absence: (some 42) holds a value, while NONE holds no value.

Conceptual view — semantic

{ type: "Option", variant: "Some", value: 42 }
{ type: "Option", variant: "None" }

variant names which case we mean; it is not a stored field. The actual object has the Option tag and a pair payload. The pair's first value is a raw Boolean saying whether a value is present; its second is the value. For None, the second position is an unused raw false.

Conceptual view — structural

Some: { type: church-ten,
        value: pair(raw-true, <contained value>) }

None: { type: church-ten,
        value: pair(raw-false, raw-false) }

Public some passes an Error argument along instead of hiding it inside Some. Expected absence and failure are different ideas. Source: Option construction and selection.

13. Result: did it succeed?

A file read can succeed or fail. Result represents those outcomes: an Ok contains the successful value; an Err contains an Error explaining the failure. Public constructors are make-ok and make-err.

Conceptual view — semantic

{ type: "Result", variant: "Ok", value: 42 }
{ type: "Result", variant: "Err", error: <Error> }

The representation uses the same idea as Option: an outer tag and a payload pair containing a raw Boolean discriminator and a value. “Discriminator” just means the value that tells the two cases apart. Here raw true means success, and raw false means failure.

See the Result payload

Conceptual view — structural

Ok:  { type: church-four,
       value: pair(raw-true, <successful value>) }

Err: { type: church-four,
       value: pair(raw-false, <Error value>) }

make-ok propagates an Error argument. In contrast, make-err deliberately accepts an Error as data so a program can inspect the Result before choosing what to do.

Option asks “was there a value?” Result asks “did the operation succeed?” A successful operation can even return an Option: read-line returns an Ok containing None at end of input, while an input failure is an Err.

Source: Result construction and access. The next section explains the Error inside an Err.

14. Errors carry their explanation

Give add a Rat and a String. Its second argument fails the runtime contract:

Complete program

#lang attalambda

(print (add 4 "hello"))

Output (no trailing newline)

ERROR(add(arg2 expected RAT got STRING))

This text is the rendered explanation of a value. The value contains a root recording what originally went wrong and a list of frames recording context as the Error passes through checked operations.

Conceptual view — semantic

{
  type: "Error",
  root: {
    kind: "TypeMismatch",
    details: {
      argument: 2,
      expected: "Rat",
      actual: "String"
    }
  },
  frames: [
    { function: "add", argument: 2, expected: "Rat" }
  ]
}

The field names, strings, numbers, and brackets are our semantic notation. The real Error is a tagged selector pair whose payload pairs the root with the frame List. The root, details, and individual frames are themselves encoded using pairs; kinds, positions, and types use small Church numerals.

An AttaLambda Error is another tagged value inside AttaLambda. It is not a Racket exception acting as the language's error mechanism. This printed program exits normally. Syntax errors and failures in the surrounding runner are a different matter.

See the Error structure and one more frame

Conceptual view — structural payload

Error  = pair(error-type, pair(root, frames))
root   = pair(type-mismatch-kind, details)
details = pair(argument-position-two,
               pair(rat-type, string-type))
frame  = pair(<String "add">,
              pair(argument-position-two, rat-type))

Those names abbreviate lambda-encoded values, not host records. A checked operation receiving an Error preserves the root and adds its own frame. Try putting the failed addition inside multiplication:

Complete program

#lang attalambda

(print (mult 2 (add 4 "hello")))

Output (no trailing newline)

ERROR(add(arg2 expected RAT got STRING)
  -> mult(arg2 expected RAT))

The root still describes the String supplied to add. The new frame says mult encountered that Error where it expected its second Rat. New frames are prepended internally; the rendered diagnostic shows them from the original failure outward.

Sources: Error structure, contract checks and propagation, diagnostic rendering.

15. Recursion without a primitive self

A lambda does not automatically receive a name referring to itself. How can a function call itself? Start by imagining a function that receives the recursive operation as an argument. A fixed-point combinator supplies the connection: it builds a value that behaves like applying that function to the value itself.

AttaLambda's rec provides syntax for that construction. Here factorial returns 1 at zero; otherwise it multiplies the input by the factorial of one less. For 5, that gives 5 × 4 × 3 × 2 × 1.

Complete program

#lang attalambda

(rec factorial n =
  (if (eq n 0)
      1
      (mult n (factorial (sub n 1)))))

(print (factorial 5))

Output (no trailing newline)

120

The example is intended for nonnegative whole inputs. A plain self-recursive def is rejected; use rec.

Desugared — expansion shape

(def factorial =
  (language-fix
    (lambda (factorial)
      (lambda (n)
        (if (eq n 0)
            1
            (mult n (factorial (sub n 1))))))))

The body now receives factorial as a parameter. language-fix is the expander's internal name for raw-fix, not a public function to call in a program. def and the multiple-argument calls then expand as before.

So rec leads to a function receiving its recursive self, then a fixed-point construction, then only lambdas and application. Lazy evaluation lets the next recursive step wait until it is needed; the chosen base case can stop the process.

How the fixed-point construction works

Source excerpt — core/fix.rkt

(def raw-fix function =
  ((lambda (self)
     (function (self self)))
   (lambda (self)
     (function (self self)))))

Call the supplied function F, and abbreviate λself.F (self self) as W. The construction is W W. One reduction gives F (W W): F receives the very construction we started with. That is the fixed-point relationship.

Nothing primitive named “recurse” is added. The equation explains the connection, not a guarantee of termination: demanding endless recursive work still runs forever.

Sources: rec expansion and fixed-point implementation.

16. Reaching the outside world

A universe of pure lambdas can calculate, but calculation alone cannot print text, read a file, or accept a network connection. Those actions are effects: interactions with the outside world.

AttaLambda builds encoded requests and passes them to a deliberate boundary called the host. The host validates each request, converts encoded values for the external operation, performs it, and returns encoded results when the operation returns.

  1. Pure AttaLambda computation builds a request.
  2. The host validates and converts it.
  3. The operating system performs terminal, file, TCP, or process work.

print renders a value to a String and passes it to stdout. stdout writes the string's contents; read-line receives a line of input. File operations read and write files; TCP operations communicate over network connections; exit ends the process.

Racket provides the execution environment, including lazy evaluation and this boundary. It is not a shortcut for implementing ordinary AttaLambda arithmetic or data operations with host numbers and records. The ordinary computation we traced remains lambda-encoded.

Sources: host dispatcher and boundary conversions.

17. Putting it together

We can now read the language as one connected construction:

  1. AttaLambda source gives us readable names and expressions.
  2. Syntactic sugar expands into simpler forms.
  3. Variables, unary lambdas, and application do the computation.
  4. Functions encode behavior and data, including selectors and pairs.
  5. Pairs give public values their type tags and payloads.
  6. Runtime contracts inspect tags and produce structured Errors.
  7. The host handles effects when the outside world is needed.

These are layers of explanation, not a sequence of runtime conversions. In particular, the object-like drawings never replace the selector lambdas. We have changed how we read the values, not what they are.
